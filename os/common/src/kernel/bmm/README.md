一、 内核态 basicmm（机制提供者）

内核态的 basicmm 代码量极小，它必须运行在特权级（Ring 0），直接与底层硬件（如 MMU - 内存管理单元）交互。它的核心职责是执行内存映射操作并保护系统安全，但不关心这些内存是用来干什么的。

它的具体职责边界包括：

    管理硬件页表： 直接操作底层硬件的页表结构（如 x86 的 CR3 寄存器、页目录和页表），执行虚拟地址到物理地址的映射。

    处理底层的缺页异常（Page Fault Catching）： 当 CPU 触发缺页异常时，basicmm 会捕获这个硬件中断。但它不负责寻找空闲的物理内存去修复它，而是将缺页异常打包成一条 IPC（进程间通信）消息，发送给用户态的 mm 服务器。

    提供内存操作的系统调用（Primitives）： 提供如 Map（映射）、Grant（授权/转移）、Unmap（取消映射）等基础原语，供用户态 mm 调用以修改页表。

    TLB 刷新： 在页表更改后，负责刷新转换后备缓冲器（TLB）。

二、 用户态 mm（策略决策者）

用户态的 mm 是作为一个独立的用户级进程（Server）运行的（运行在 Ring 3）。它负责系统全局的内存分配逻辑、记账和高级内存特性。

它的具体职责边界包括：

    虚拟内存区域管理（VMA）： 记录每个用户进程的虚拟地址空间布局（哪些地址是代码段、数据段、堆、栈，哪些是 mmap 的文件）。

    物理内存分配策略： 维护空闲物理内存链表（如伙伴系统、Slab 分配器）。当进程需要内存时，决定分配哪一块物理页框。

    缺页异常的逻辑处理（Page Fault Resolution）： 接收来自内核 basicmm 发来的缺页 IPC 消息。根据 VMA 判断该缺页是否合法：

        如果不合法（越界访问），则发送信号杀死进程（如 Segfault）。

        如果合法，则从空闲物理内存池中分配一页，并调用内核的 Map 原语，指示内核建立映射。

    页面置换与 Swap： 决定哪些内存页因为不常用需要被写入磁盘（Swap Out），哪些需要从磁盘读回（Swap In）。这些复杂的磁盘 I/O 逻辑全部放在用户态。

    内存共享与 IPC 载体： 管理多个进程之间的共享内存（Shared Memory）权限。

三、 边界交互示例：一次缺页异常（Page Fault）的全过程

为了更清晰地理解这个边界，我们可以看一个进程触发缺页异常时，basicmm 和 mm 是如何跨界合作的：

    触发异常： 用户进程 A 访问了一个未分配物理内存的虚拟地址，MMU 触发硬件缺页异常。

    内核态 basicmm 介入： 内核捕获异常，读取导致异常的虚拟地址和错误码，暂停进程 A。

    跨越边界（向上）： basicmm 生成一条 IPC 消息（内容大致为：“进程 A 在地址 0x80004000 发生了写缺页”），发送给用户态的 mm 服务器。

    用户态 mm 决策： mm 收到消息，检查进程 A 的 VMA 结构，发现这是一个合法的堆扩展请求。于是，mm 按照自己的算法（如伙伴算法）在用户态的数据结构中找到一个空闲的物理页框（例如 PFN 0x1234）。

    跨越边界（向下）： mm 通过系统调用向内核态 basicmm 发送指令：“请将进程 A 的虚拟地址 0x80004000 映射到物理页框 0x1234，权限为可读写”。

    内核态 basicmm 执行： basicmm 收到指令，修改进程 A 的硬件页表，然后唤醒进程 A。

    恢复执行： 进程 A 继续执行，缺页问题已解决。
